# Discovery experiments for the unrestricted interval game

This package makes GitHub Actions search for new strategies. The existing
`.github/workflows/finite-reduction.yml` remains the exact replay workflow.
The separate `.github/workflows/discovery.yml` has five independent searches,
selects the current campaign from `campaign.json`, preserves candidates and checkpoints, and independently replays any
prospective improvement before changing the reported unrestricted bracket.

**A completed or green search is not a mathematical improvement.** The exact
unrestricted value and a terminating sufficient equilibrium class remain open.

## What the experiments search

| Experiment | New variables or paths | Response and certification |
|---|---|---|
| Princess proximal | Transport-constrained profile on grid 32, priced on grid 64 | Bundle stabilization; complete integer pricing when cached responses no longer separate |
| Princess randomized | Seeded convex perturbation of the starting CDF on grid 32, priced on grid 128 | Independent random physical response seeds; complete integer oracle |
| Princess plain | Larger grid-64 transport profile, priced on grid 128 | Unstabilized master optimization, with the same exact lower gate |
| Monster mutations | Lift the retained law to grid 128; propose legal new starts and turn sequences | Full Qout master, exact rational physical law and all-Princess closure replay |
| Monster priced | Grid-64 physical paths generated by exhaustive response pricing | Independent search trajectory and exact all-Princess closure replay |

The Princess searches optimize the CDF itself. Known Monster responses are
counterexample generators, never lower certificates. Every saved exact lower
comes from a completed exhaustive native response calculation on an exactly
repaired integer field. Its unrestricted **game-value** lower subtracts the
proved `1/(2n)` transfer allowance. This does not give that same CDF an
unrestricted security guarantee.

Promising Princess fields receive a finer `n=512` exact pricing pass. The
allocation screen uses the coarse objective minus the prospective fine-grid
penalty. That number is a heuristic screen only: the actual refined minimum
may be substantially worse. The final campaign gate separately runs the
standard-library/C++ reader, full integer response replay, exact Fraction
transfer arithmetic, and the independent JavaScript Qout field checker on a
prospective new game lower. These are computer-assisted analytical
certificates that trust the existing integer recurrence and pruning, whose
small-bank cases have exhaustive Fraction regressions. A separate full-bank
BigInt replay is available with `summarize.py --bigint`; it is an additional
implementation cross-check, not a mathematical premise. Reports explicitly
say whether that extra replay was performed. No Lean kernel verification is
claimed.

Every proposed Monster mixture is rationalized and checked using the existing
physical Qout flow/cut verifier. Its exact upper covers every Princess path.
Its floating master objective is recorded separately. A physically invalid
path or causal clock causes verification to fail; no aggregate unlifted clock
solution is accepted.

## Run locally

Python 3, NumPy 2.3.5, SciPy 1.17.0, a C++17 compiler, and Node are required
for discovery. Exact replay uses the existing verifiers' documented runtimes.
Run from the repository root:

```bash
python3 packages/interval_discovery/princess_search.py \
  --n 64 --profile-grid 32 --family proximal --seed 1701 \
  --iterations 160 --seconds 1200 --refine 512 --refine-seconds 1500 \
  --profile-seed packages/interval_clock_grid/lower_n256_field.json \
  --monster-seed packages/interval_clock_grid/upper_n64_physical.json.gz \
  --output results/princess-proximal

python3 packages/interval_discovery/monster_search.py \
  --n 128 --family mutations --seed 161803 --iterations 60 --seconds 1800 \
  --profile-seed packages/interval_clock_grid/lower_n256_field.json \
  --output results/monster-mutations

python3 packages/interval_discovery/summarize.py results --output campaign
```

`--seconds` is an experiment budget, not a proof truncation. An interrupted
calculation cannot become a new lower certificate. The Princess driver stops
the whole subprocess group and preserves the last *completed* exact field.
The Monster driver retains its already checked physical law when its search
budget ends. GitHub has an additional job timeout, and its artifact-upload
step runs after successful and failed searches.

## Reproducibility and restart

Artifacts retain exact candidate inputs, discovered physical paths, floating
LP checkpoints, exact rational objective values, seed and RNG state where
applicable, solver logs, source and input SHA-256 hashes, package versions,
compiler version, commit SHA, and Actions run identity. `structure.json`
contains CDF traces or physical-law support diagnostics. These are candidate
observations, not equilibrium theorems.

Resume the Princess command with `--resume` and the same output directory and
search parameters. Resume the Monster command with
`--resume results/monster-mutations/checkpoint.json`. The saved physical upper
is revalidated before reuse. The workflow also accepts an earlier discovery
`resume_run_id` and restores the matching per-experiment artifact. A manual
dispatch is available when GitHub exposes that workflow on the default branch;
the checked-in push trigger works on the research branch without that step.

The workflow retains artifacts for 90 days. Mathematically useful winners
should also be committed as compact certificate inputs with their hashes;
artifact retention alone is not permanent archival storage.

`campaign.json` retains the registry of all five families and explicitly
selects which should run next. This avoids repeating successful expensive
experiments just to resume a failed one. The checked-in continuation selects
`princess-plain` and restores its saved artifact from the first campaign.
Workflow dispatch can override the selection with comma-separated experiment
IDs. `configure_campaign.py` validates the selection and run IDs before
constructing the Actions matrix.

The persistent HiGHS backend now gives each solve a fresh allowance relative
to its accumulated runtime. Main simplex and any IPM fallback share that
allowance. The fix arrived in the concurrent research commit `6655765` and
is reused by the resumed discovery; the exact pricing engine is unchanged.

A cold restart can still exhaust a genuine single-solve LP allowance. The
driver records this as `BUDGET_STOPPED` only when a completed exact field is
already saved. It retains that field, reports that the unfinished LP supplied
no objective, and leaves unexpected solver errors as failures. Budget stops
and successful runs without a new certified bound are not mathematical
improvements.

## Meaningful regression tests

```bash
python3 packages/interval_discovery/test_princess_search.py
python3 packages/interval_discovery/test_monster_search.py
python3 packages/interval_clock_grid/normalized_native/test_persistent_highs.py --output /tmp/persistent-discovery-replay.json
python3 packages/interval_discovery/test_configure_campaign.py
```

These exercise physical path legality, completed exact pricing, refinement,
independent BigInt/flow-cut replay and restart. They do not repeat the large
frozen certificate searches merely to test orchestration.

The current campaign summary loads the retained n=256 lower and the archived
CI-discovered Monster upper. It recomputes improvement comparisons against
those values while retaining each source manifest's historical claim. A
candidate that improved an older checkpoint cannot overwrite a stronger
bound added concurrently. Observed run outcomes and artifact links are kept
in [HANDOFF.md](../../HANDOFF.md).

## What would close the problem

The computations must identify a law or uniformly approaching Princess family
whose all-Monster lower equals a physically realized all-Princess upper, or
prove an equilibrium-specific finite sufficient classification. Optimizing
larger meshes with a known error is useful evidence and certification, but
does not by itself prove exact termination. If a campaign yields only tiny
weight changes or no improvement, retain its strongest counterexamples and
reassess the CDF geometry instead of treating more grid points as a solution.
